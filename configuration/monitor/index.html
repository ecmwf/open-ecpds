    Monitor: ecmwf.properties¶

    The Monitor's ecmwf.properties configures its Master connection, HTTPS web interface, status calculations, login presentation and display defaults. This reference includes options omitted from the shipped file, not just the template's assignments.

    See also the Master and Data Mover references. The Master's schedulers and the Mover's portal are configured in their own processes, not here.

    File location and overrides¶

    The source template is etc/monitor/conf/ecmwf.properties. Its RPM path is /usr/local/ecpds/monitor/conf/ecmwf.properties; the launcher selects it with the ecmwf.properties JVM property.

    Use /etc/ecpds/monitor.cnf or the container/service environment for launcher values such as the Master address, listener ports and keystore password. ${...} placeholders in the template reference JVM properties or other sections; they are not arbitrary environment-variable substitutions.

    The final #include "${monitor.etc}/ecmwf.properties" loads local overrides, normally from /etc/ecpds/monitor/ecmwf.properties. It is already an active directive despite its leading #. The include must not refer back to the same file. See the configuration syntax and loading rules.

    For example, a local override can change display preferences without copying the complete template:

    [MonitorPlugin]
productsToShowCount=15
productsToShowPeriod=72
authMode=password,otp

[Server]
globeImageryCacheDir=/var/lib/ecpds/monitor/globe-imagery
globeLabelsCacheDir=/var/lib/ecpds/monitor/globe-labels

    Create persistent cache directories with write access for the Monitor service account. Restart the Monitor after configuration changes unless the relevant feature explicitly supports live updates.

    Reading this reference¶

    Code fallback is the reader's value when an option is absent; shipped value is the explicit template assignment. A dash means no assignment. Multiple fallbacks are listed separately where consumers differ. null means no fallback value, and is not a promise that the option is optional. Java expressions indicate context-dependent defaults; links identify their readers. Credentials are not reproduced.

    Rows marked template entry have no direct literal reader in this process's reviewed sources. A template reference or shared entry is not necessarily an active Monitor setting; named-socket and open-map readers are described below.

    Names are case-sensitive. Use explicit suffixes such as 30s or 5m for duration-reading options: bare configured durations are hours. Plain numeric options have their own units. In particular:

    Setting Unit or scope
    [Monitor] delay Duration for external service-status reporting, not web-page refresh.
    [MonitorPlugin] refreshDelay Milliseconds between background destination-status refreshes.
    statusCalculatorTimeout, destinationProductStatusResetterTimeout Minutes; watchdogs for stuck background tasks, not HTTP request timeouts.
    productsToShowPeriod Hours ahead in the product-status window.
    productStatusEventMaxAge Days.
    Socket timeouts Milliseconds.

    Important distinctions¶

    [Monitor] activated controls external monitoring integration. It does not enable or disable the browser UI. [MonitorPlugin] statusCalculator controls background status calculations.

    authMode chooses which credential methods the login form displays (password, otp or password,otp). It does not disable server-side authentication or configure the OTP provider. See TOTP Authentication.

    wantClientAuth=yes asks for optional TLS client certificates; it does not require clients to present one. The retained template flags checkIsSecure and production have no direct readers in the current Monitor implementation; they must not be treated as HTTPS enforcement or security-hardening switches. See TLS Certificates.

    The Monitor uses both [MonitorPlugin] and selected [HttpPlugin] settings: the latter controls shared Jetty sizing and HTTP/2 settings. TLS stores can also be overridden by [HttpPluginSSL].

    [Server] eventRepository and [StorageRepository] eventSize/eventDelay are retained shared template entries, not controls for the Master's event journal. Configure operational-event export and journaling on the Master, not the Monitor.

    Named socket sections¶

    SocketConfig.load reads the following keys from a component's named section. Common section names for this service are CallBack, RMIServerSocketFactory, RMIClientSocketFactory and MonitorPlugin (the latter uses the socket configuration for its bind address, not every raw-socket option). A transfer module or plugin must actually use that socket implementation for its settings to apply; Jetty HTTP listeners and third-party transfer clients do not automatically honour every low-level socket option.

    Basic options inherit the values in [SocketConfig] shown above; the advanced TCP options from tcpCongestion onward default to unset and are read from the named section, not from the global [SocketConfig] defaults. Advanced options depend on OS/socket support. Caller-supplied addresses, ports and module/Host settings may override socket defaults.

    Option(s) Meaning
    listenAddress Local bind/source address.
    publicAddress Advertised address, distinct from the local bind address.
    receiveBufferSize, sendBufferSize Bytes; -1 leaves the OS default.
    soTimeOut Read timeout in milliseconds; aliases soTimeout and timeOut are tried in that order when the preferred spelling is absent.
    connectTimeOut Connection timeout in milliseconds.
    backLog Pending incoming-connection queue length.
    keepAlive TCP keepalive switch.
    tcpNoDelay TCP_NODELAY switch.
    reuseAddress SO_REUSEADDR switch.
    interruptible Use the interruptible socket implementation.
    privilegedLocalPort Allocate a local source/listening port from the configured local range.
    minPrivilegedPort, maxPrivilegedPort Inclusive local-port range; inherited base defaults are 500 and 1023.
    trace Socket diagnostics.
    host, port Default remote endpoint when the caller does not supply one.
    serverPort Local listening port; 0 requests an automatically assigned port.
    tcpCongestion Congestion-control algorithm name.
    soMaxPacingRate Maximum socket pacing rate, bytes/s.
    tcpMaxSegment Maximum TCP segment size, bytes.
    tcpTimeStamp TCP timestamps switch.
    tcpWindowClamp TCP receive-window clamp, bytes.
    tcpKeepAliveTime Idle time before keepalive probes, seconds.
    tcpKeepAliveInterval Time between keepalive probes, seconds.
    tcpKeepAliveProbes Keepalive probe count.
    tcpLingerEnable Enable linger-on-close.
    tcpLingerTime Linger timeout, seconds.
    tcpUserTimeout Maximum unacknowledged-data time, milliseconds.
    tcpQuickAck TCP quick-acknowledgement switch.

    Constructed HTTPS/TLS keys¶

    The HTTPS helper constructs [Security] SSL<Key> names and otherwise consults the corresponding javax.net.ssl.<key> JVM property. Its actual keys are SSLKeyStore, SSLKeyStorePassword, SSLKeyStoreType, SSLTrustStorePath, SSLTrustStorePassword and SSLTrustStoreType.

    SSLTrustStorePath is the HTTPS helper's spelling; the generic socket TLS reader separately uses SSLTrustStore. Do not assume these are aliases. The explicit [HttpPluginSSL] map takes precedence over the HTTPS helper's normal store-selection branch. MQTT uses [Security] SSLKeyStore and SSLKeyStorePassword through its own helper.

    Plugin and module families¶

    [PluginList] is an open map of plugin names to definitions:

    [PluginList]
name=implementation.Class@/path/to/plugin,option=value

    The library path and per-plugin options depend on the plugin. Server plugins support maxConnections and inverseResolution; deleting or adding a plugin definition changes which services start. These are options inside the value, not new top-level ecmwf.properties groups. See Plugin Infrastructure.

    [ECtrans] is an open family of global transfer-option defaults, with keys module.option (for example, ftp.passive). Its option set is defined by ECtransOptions and the selected module, not a fixed list of literal Cnf keys. Entity/transfer setup values can override these defaults. The complete option/default references are:

    • ECtrans common options and the protocol pages under Transfer Modules.
    • Host options, Destination options, Web User options and Data User options.

    These entity options are not interchangeable with service sections. Some options are only meaningful for a particular module or execution role.
