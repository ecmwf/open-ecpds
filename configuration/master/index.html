    Master: ecmwf.properties¶

    The Master's ecmwf.properties controls scheduling, database access, public services, operational events and shared infrastructure. This reference includes options read by the implementation even when they are absent from the shipped file.

    Other services have separate references: Monitor and Data Mover.

    Identity extensions¶

    [AuthenticationExtension] class and [UserDirectoryExtension] class select optional, trusted Master identity providers. Both default to blank (disabled). Provider-specific options belong in the same section. Configuration is read at startup and requires a restart; a configured provider that cannot start fails Master startup. See Identity extensions for installation, lifecycle and authentication precedence.

    The optional ECaccess identity extension uses host and port in each identity-provider section and requires explicit bounded [RMIClientSocketFactory] connection/read timeouts.

    [RemoteServiceExtensions] explicitly maps service IDs to provider configuration sections. It defaults to no registrations. See Remote service extensions and the optional ECaccess transfer module.

    [InteractiveLoginExtension] class independently enables browser-based Monitor login. It defaults to blank. [InteractiveLoginMapping] maps local WebUser IDs to JSON objects containing the verified external issuer and subject. See OpenID Connect login for the bundled provider, full configuration and account requirements.

    File location and configuration layers¶

    The source template is etc/master/conf/ecmwf.properties. RPM installations place it in /usr/local/ecpds/master/conf/ecmwf.properties. The launcher selects the file with the ecmwf.properties JVM property; container mounts can change where its contents are stored.

    Use /etc/ecpds/master.cnf or the container/service environment for launcher settings such as addresses, ports, database connection details and secrets. The launcher translates supported variables into the JVM properties referenced by the template. Arbitrary environment variables do not automatically become ecmwf.properties options.

    The final directive:

    #include "${master.etc}/ecmwf.properties"

    loads a local override file from the launcher's master.etc directory if it exists and is readable. Despite the leading #, #include is an active configuration directive, not an ordinary comment. It must start at the beginning of the line. The supplied service layout uses a separate directory for this file, normally /etc/ecpds/master; do not point an include back to the file containing it. An unreadable or missing include produces a warning.

    An override contains only the sections and values to change, for example:

    [TransferScheduler]
queueSize=80

[StoragePolicy]
enabled=no
interval=1m

    Restart the affected service after changing configuration unless a feature's documentation explicitly describes runtime reload support. Many values are cached when classes or services initialize. #reload "Group" permits the configuration loader to reload that group, but does not make every consumer apply a changed value dynamically.

    Syntax and defaults¶

    Syntax Meaning
    [Group] followed by key=value A case-sensitive section and option name.
    # text A comment, except recognized directives such as #include, #reload and #property.
    ${master.data} A JVM system property supplied by the launcher.
    ${Login[hostName]} Another option in this configuration.
    ${fully.qualified.Class.method()} A supported static-method substitution used by the templates.
    yes / no, true / false Boolean values.
    30s, 5m, 24h, 7d Explicit durations for duration-reading options; ISO-8601 durations are also accepted.

    Duration units depend on the reader

    Options read as durations treat a bare configured number as hours, not milliseconds. Plain integer options may instead use milliseconds, seconds, minutes, bytes or counts. For example, [Monitor] delay=120 means 120 hours, while [SocketConfig] connectTimeOut=30000 means 30 seconds. Duration defaults passed by the Java implementation are milliseconds; the tables below label these separately from configured values.

    The catalogue distinguishes code fallback (what a particular reader uses when the option is absent) from shipped value (what the template explicitly sets). They are not necessarily equal. Removing a setting can therefore change behaviour. A dash in the shipped column means it is not assigned in the template. null means that reader supplies no value, not that the option is safe to omit. An empty list and an empty string are shown explicitly.

    Context-dependent Java expressions are retained rather than replaced by a guessed constant. Where readers use different fallbacks, they appear on separate rows with links to their source. File-content options interpret the configured value as a path, but their fallback is content. Shipped credentials are not reproduced here.

    Entries marked template entry have no direct literal reader in the reviewed sources. They may be consumed through substitutions or retained for compatibility; their presence alone is not evidence of an active runtime switch. Named-socket and open-map readers are documented separately.

    Operational guidance¶

    • Enable native log export, journaling and tracing independently; see Event Logging. Only the Master needs Collector connectivity and OpenTelemetry connection settings.
    • [StoragePolicy] enabled=yes can enforce existing policies immediately. Read Storage Lifecycle Policies before enabling it.
    • Scheduler switches in [Server] enable workers; [Scheduler] configures their cadence, concurrency and watchdogs. Increasing concurrency also increases database, memory and Mover load.
    • Repository *Size settings select storage-worker thread counts, not queue capacities or records per batch. Do not use them as retention limits.
    • Keep RMI and callback interfaces on trusted networks. Public service bind addresses and advertised addresses serve different purposes.
    • Protect credentials and keystores with restrictive file permissions. trustAllCerts, checkCertificates=no and plaintext proxy connections weaken transport protection; shipped values are not security recommendations.

    Named socket sections¶

    SocketConfig.load reads the following keys from a component's named section. Common section names for this service are CallBack, RMIServerSocketFactory, RMIClientSocketFactory, ECpdsPlugin, FtpPlugin, FTPPassiveSocket, FTPActiveSocket, ProxySocket and ManagementEXEC; transfer/helper code can also use ECauthModule, FtpPASV, FtpPORT, FtpOPEN, HTTPSocketConfig, GCSSocketConfig, S3SocketConfig, WebDavModule, JSftp, TelnetWrapper and ECios. A transfer module or plugin must actually use that socket implementation for its settings to apply; Jetty HTTP listeners and third-party transfer clients do not automatically honour every low-level socket option.

    Basic options inherit the values in [SocketConfig] shown above; the advanced TCP options from tcpCongestion onward default to unset and are read from the named section, not from the global [SocketConfig] defaults. Advanced options depend on OS/socket support. Caller-supplied addresses, ports and module/Host settings may override socket defaults.

    These sections accept names determined by users, services or network addresses, so there is no finite list of key names:

    Section / key pattern Default when absent Meaning

    [Services] <serviceName> Service unavailable External execution endpoint in host:port form. Uses [ManagementEXEC] socket settings.
    [Restricted] <user> No configured root restriction Comma-separated regular expressions matched against the connecting root's resolved hostname.
    [Roots] <user> Empty value Static authentication credential for that user; not a filesystem-root path. Keep this secret.

    [GeoIP] forced.<address-or-prefix> Normal GeoIP resolution Forced latitude,longitude,region,country,city for matching addresses.
    [DestinationTypes] <position>.<id>.<category> Built-in Destination types Additional Destination type labels, in position.id.category=label form.

    Forced GeoIP entries are checked before database lookup. Local/private addresses otherwise skip GeoIP lookup; this does not prevent name resolution. See Live Earth monitoring.

    FTP mapping and per-user families¶

    Section / key pattern Default when absent Meaning
    [FtpPlugin] restrict.<user> No prefix restriction Require the client's textual IP address to start with the configured prefix. This is not CIDR syntax.
    [FtpAliases] <domain> Empty list Alias list for the selected virtual domain.
    [FtpDomainList] <domain> No mapping; * is the fallback Virtual domain to backing-domain mapping.
    [FtpModuleList] <extension> Default * module list Extension-specific FTP module definitions.
    [Filter] pre.out.<name> No direct reader in current sources Retained template definitions for file-to-file filter commands using $1 and $2 paths.
    [Filter] fly.out.lbzip2, fly.in.lbzip2, fly.out.zstd, fly.in.zstd No configured command Streaming compression/decompression commands.

    Streaming filter executables must be installed on the machine executing them. Adding a definition does not apply it to every transfer; the current stream manager selects the named lbzip2 or zstd command when using that format.

    Plugin and module families¶

    [PluginList] is an open map of plugin names to definitions:

    [PluginList]
name=implementation.Class@/path/to/plugin,option=value

    The library path and per-plugin options depend on the plugin. Server plugins support maxConnections and inverseResolution; deleting or adding a plugin definition changes which services start. These are options inside the value, not new top-level ecmwf.properties groups. See Plugin Infrastructure.

    [ECtrans] is an open family of global transfer-option defaults, with keys module.option (for example, ftp.passive). Its option set is defined by ECtransOptions and the selected module, not a fixed list of literal Cnf keys. Entity/transfer setup values can override these defaults. The complete option/default references are:

    • ECtrans common options and the protocol pages under Transfer Modules.
    • Host options, Destination options, Web User options and Data User options.

    These entity options are not interchangeable with service sections. Some options are only meaningful for a particular module or execution role.
